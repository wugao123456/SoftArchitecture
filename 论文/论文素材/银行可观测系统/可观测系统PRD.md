# 大型金融机构一体化智能运维平台（龙舟模式）- 产品需求文档 (PRD)

> 文档定位：本PRD用于软件架构师考试论文学习。项目就是中国建设银行"龙舟运维平台"（广通优云与建行云共创的生态化运维平台）的建设理念，围绕大型金融机构IT系统在**规模化、异构化、强监管**三重挑战下的运维数字化转型展开。平台采用 **Java 微服务 + Spark + Elasticsearch** 技术栈，构建"采、算、存、控、用、营"一体化运维底座。

---

## A. 项目背景与产品概述

### A.1 项目背景

我司中标某全国性大型商业银行"一体化智能运维平台"建设项目。该行IT运维面临**规模化、异构化、强监管**三重挑战：

**规模化**：全行3大数据中心、50余家分支机构、超10万台服务器、1000+套业务系统日均产生运维数据超500亿条。传统烟囱式监控工具存在性能与扩展瓶颈，核心交易系统（支付、转账、代发薪等）故障时，单源告警即达数万条/分钟，运维人员被告警风暴淹没，无法快速定位根因，严重时触发银保监通报。

**异构化**：基础设施横跨大型机、X86物理机、虚拟化、容器云、信创国产化等多元架构；技术栈涵盖传统Java EE、分布式微服务、云原生、大数据组件；运维工具分属不同厂商，指标口径不一、数据孤岛严重，缺乏统一的运维对象模型与服务接口，无法支撑跨域关联分析与根因定位。

**强监管**：需满足等保三级、《商业银行信息科技风险管理指引》《银行业金融机构信息科技外包风险管理指引》等要求，全链路操作可追溯、审计日志留存≥180天、敏感数据不出内网。同时监管对业务连续性（RPO=0、RTO≤5min）、变更合规、应急演练有明确硬性指标。

通过**平台化+生态化（OASIS模型）**，将运维共性组件下沉为统一平台，上层以服务目录形式构建近百个运维场景应用，联动10余家合作厂商共创，可实现3大数据中心+50+分支机构的一体化管理，形成金融行业运维数字化转型的典型范式。本项目即借鉴该模式，结合本行实际进行落地。

### A.2 产品概述

**一体化智能运维平台**（Integrated Intelligent Operations Platform, IIOP）是面向大型金融机构构建的企业级运维数字化底座，采用**"搭平台、做场景"**建设思路，自下而上构建四大平台：**采控平台**（统一采集与控制）、**数据平台**（统一运维数据模型与计算）、**业务平台**（共性服务组件与服务目录）、**开发平台**（运维场景应用开发生态），并在其上叠加 **AIOps智能运维能力**（实时感知→智慧认知→智能决策→自动执行），实现从"被动救火"到"主动预防+智能自愈"的转型，支撑两地三中心一体化运营。

### A.3 建设目标

1. **统一采控**：构建"采控即服务"的分布式采控体系，纳管10万+节点，支持毫秒级采集、1秒级运算，统一指标/日志/链路/拓扑数据口径。
2. **数据中台**：打通运维数据孤岛，建立统一运维数据模型与指标目录，支撑多源数据融合、清洗、订阅与多维分析。
3. **生态化场景**：基于服务目录与低代码开发平台，支撑运维场景APP快速构建与生态共创，沉淀100+运维场景应用。
4. **AIOps智能**：异常检测误报率降低60%，告警风暴收敛比≥80%，根因分析Top3准确率≥75%，故障自愈覆盖率≥50%。
5. **合规可控**：通过等保三级测评，全链路审计可追溯，敏感数据加密存储且不出内网，满足银保监监管要求。

### 业务规模假设

* 接入监控对象：≥ 100,000 台服务器（含物理机/虚机/容器）、1,000+ 业务系统、日均运维数据量 ≥ 500 亿条。
* 告警量：正常日均告警 ≤ 20,000 条；故障场景峰值告警 ≤ 100,000 条/分钟。
* 两地三中心：3 个数据中心、50+ 分支机构一体化纳管。
* 并发用户：≤ 500 人同时在线操作；生态场景应用 ≥ 100 个。

## C. 产品特性

1. **统一采控平台（采控即服务）**：分布式采控体系，纳管多中心多网络环境，支持Prometheus/Zabbix/SNMP/JMX/Syslog/Filebeat/SkyWalking等多协议，脚本化插件化扩展，万台设备秒级监控，毫秒级采集、1秒级运算。
2. **运维数据平台（统一数据模型）**：打通指标、日志、链路、拓扑、CMDB、工单等数据孤岛，统一运维对象模型与指标目录，内置丰富计算算子，支持流式/批处理计算与多场景数据订阅消费。
3. **运维业务平台（服务目录+共性组件）**：封装监控、告警、自动化、流程、CMDB等共性服务组件，以服务目录形式对外提供，运维应用可灵活搭建，支持API治理与微服务自监控。
4. **运维开发平台（生态共创）**：运维场景应用全生命周期管理，提供低代码/多语言开发能力、集中代码托管与版本控制、丰富开发资源与样例，支撑合作厂商与内部团队共创运维场景APP。
5. **一体化多维监控**：覆盖基础监控、应用监控、链路监控、网络监控、业务监控、小样本交易监控（滑动窗口累计），以应用为中心策略化松耦合指标与资源关联。
6. **告警风暴抑制与根因分析**：基于规则引擎实现告警过滤、压缩、归并、升级，结合CMDB拓扑关联、时间序列相关性与因果推断，输出Top3根因，收敛比≥80%。
7. **AIOps智能运维**：感知层（无监督异常检测+动态基线）、认知层（知识图谱+因果推断+变更关联根因分析）、决策层（时序预测+容量预警+处置方案推荐）、执行层（Runbook编排+自动处置+自愈验证）。
8. **自动化运维与自愈**：一键式版本部署（自动化率≥90%）、变更自动协同与一键回退、秒级资源扩缩容、动态流控、预案自动执行与效果验证，降低MTTR。
9. **运维服务目录与流程**：基于ITIL+DevOps双态运维理念，将运维活动封装为服务目录，对接流程引擎实现服务请求、变更、事件、问题全流程闭环。
10. **智能对话运维助手（AIOps Copilot）**：对接行内私有化大模型，支持自然语言查询、告警智能问答、报告自动生成、运维知识问答，数据不出内网。
11. **多通道通知与工单联动**：邮件、短信、企业微信、钉钉、语音电话、Webhook，按级别/排班/升级策略路由，P0/P1自动创建ITSM工单并回写。
12. **多维运营分析与可视化**：告警趋势、SLA、MTTA/MTTR、告警质量评分、运维效能大盘，支持ECC监控中心态势感知展示。
13. **安全合规与审计**：等保三级、RBAC细粒度权限+数据隔离、全链路HTTPS、敏感数据加密、操作审计日志留存≥180天。

## D. 功能需求

### D.1 统一采控平台（Collection & Control Platform）

| 功能 | 描述 |
|------|------|
| 分布式采控体系 | 面向资源的采控能力服务化封装，支持大规模节点采控任务秒级调度，跨数据中心多网络环境统一采控。 |
| 多协议适配 | 支持 Prometheus Remote Write、Zabbix API、SNMP、JMX、HTTP Pull、Syslog、Filebeat、SkyWalking、OpenTelemetry 等协议。 |
| 采集标准化 | 统一运维对象模型与指标模型（metric_name、tags、value、timestamp），自动清洗与字段映射，建立指标目录与血缘。 |
| 采控脚本化插件化 | 采控能力脚本化、插件化按需扩展，新增监控源只需开发适配器，无需改动核心。 |
| 采集任务管理 | 采集目标注册、采集频率配置（毫秒级~5min）、黑白名单、采集状态自监控。 |
| 数据缓冲与削峰 | Kafka 作为采集缓冲层，应对采集洪峰；消费失败重试与死信队列，保障数据零丢失。 |
| 小样本交易监控 | 针对低频交易（如债券通日均仅10笔）采用"滑动窗口累计"算法，解决常规监控无法覆盖的小样本异常检测。 |

### D.2 运维数据平台（Data Platform）

| 功能 | 描述 |
|------|------|
| 多源数据统一接入 | 打通指标、日志、链路、拓扑、CMDB、工单、变更等数据源，灵活清洗融合。 |
| 统一数据模型治理 | 抽象运维对象（应用/服务/主机/中间件/数据库）模型，提升运维数据质量，建立指标元数据与质量评分。 |
| 流式/批处理计算 | 内置丰富计算算子，Spark Streaming 实时计算 + Spark SQL 批处理，支撑秒级运算与多维聚合。 |
| 海量数据存储 | ES 存告警/事件/日志（冷热索引）、HDFS 存历史指标归档、MySQL 存元数据、Redis 存热数据。 |
| 数据订阅消费 | 多场景数据订阅与消费接口，支撑上层场景应用按需获取数据。 |

### D.3 一体化监控与告警（Monitoring & Alerting）

| 功能 | 描述 |
|------|------|
| 多维监控覆盖 | 基础监控（主机/网络/存储）、应用监控（JVM/接口）、链路监控（调用链）、业务监控（交易量/成功率）全栈覆盖。 |
| 应用为中心监控 | 策略化松耦合指标、阈值与资源关联，实现应用、资源、网络全方位自监控。 |
| 规则可视化编排 | 拖拽式画布，支持阈值规则、趋势规则、同环比规则、组合条件（AND/OR）、TopN。 |
| 规则模板与版本 | 内置主机/中间件/数据库场景模板，规则增删改走版本化，支持回滚、对比、审批流。 |
| 规则弹性下发 | 规则DSL编译为Spark执行计划，灰度下发、冷热分层（高频规则下沉流处理热路径）、秒级生效、紧急撤回。 |
| 实时规则匹配 | Spark Streaming 消费Kafka指标流，毫秒级匹配规则命中生成告警，P99规则匹配时延≤3s。 |
| 告警事件化 | 告警升级为事件，状态流转：触发→确认→分派→处理中→已解决→已关闭→复盘归档。 |
| 告警分级与升级 | P0/P1/P2/P3分级，告警持续未确认自动升级级别与通知人。 |

### D.4 告警风暴抑制与根因分析（Storm Suppression & RCA）

| 功能 | 描述 |
|------|------|
| 时间窗口聚合去重 | 同一规则+同一指标+同一维度在时间窗口内只生成一条告警，N秒内聚合为汇总告警。 |
| 拓扑关联抑制 | 基于CMDB服务依赖拓扑，上游故障自动抑制下游告警（如数据库宕机抑制所有依赖应用告警）。 |
| 相关性聚合 | 通过告警时间序列相关性（同时发生、同源指标）将相关告警聚合成父告警。 |
| 根因分析（RCA） | 基于知识图谱反向追溯 + 因果推断（Granger/PC算法）+ 变更关联，输出Top3疑似根因及置信度。 |
| 抑制规则配置 | 支持维护窗口抑制、手动抑制规则配置，风暴告警以"父告警+子告警"树形展示。 |
| 告警归档 | 已关闭告警/事件归档至ES冷索引，支持长期查询与复盘分析。 |

### D.5 自动化运维与故障自愈（Automation & Self-healing）

| 功能 | 描述 |
|------|------|
| 一键式版本部署 | 变更自动协同、一键式回退，投产日应用版本自动化部署率≥90%，高频投产零失误。 |
| 资源弹性扩缩容 | 全链路容量评估，秒级资源扩容、分钟级动态资源池扩缩容，支撑大促场景。 |
| 动态流控 | 基于实时负载的动态流量控制，保护核心系统稳定。 |
| 预案自动执行 | 告警命中后自动触发预定义处置预案（重启服务、扩容Pod、切换流量）。 |
| 处置审批流 | 高危处置动作需人工审批，审批通过后执行，支持定时/灰度执行。 |
| 执行效果验证 | 处置执行后自动验证指标是否恢复，未恢复则升级或切换备选预案。 |
| 自愈成功率统计 | 统计各类预案自愈成功率与平均恢复时间，持续优化预案库。 |

### D.6 AIOps智能运维（Intelligent Operations）

| 功能 | 描述 |
|------|------|
| 无监督异常检测 | 基于孤立森林、LSTM、3-Sigma等算法对指标进行无监督异常检测，无需预先配置阈值即可发现异常波动。 |
| 动态基线学习 | 自动学习指标周期性（日/周/月）与趋势，生成动态基线，告警阈值自适应调整，误报率降低60%。 |
| 多指标关联异常 | 基于多指标相关性矩阵，检测一组关联指标的协同异常（如CPU突增伴随磁盘IO飙升）。 |
| 知识图谱根因分析 | 基于CMDB+调用链构建服务依赖知识图谱，故障时沿图谱反向追溯根因节点。 |
| 因果推断定位 | 基于告警时间序列因果关系（Granger因果/PC算法），区分"因告警"与"果告警"。 |
| 变更关联分析 | 自动关联近期发布变更、配置变更、扩容操作，判断故障是否由变更引发。 |
| 时序趋势预测 | 基于Prophet/ARIMA预测指标未来走势，提前预警潜在故障。 |
| 容量水位预警 | 对磁盘、内存、连接数等容量指标，预测达到阈值的时间并提前告警，输出扩容建议。 |
| 故障案例库与处置推荐 | 沉淀历史故障现象、根因、处置步骤，告警触发时基于ES向量检索推荐Top3处置方案。 |
| Runbook编排与执行 | 将标准处置流程编排为可执行Runbook，支持一键/半自动执行，事件关闭后自动提取处置记录入库。 |
| 智能对话运维助手 | 对接行内私有化大模型，支持自然语言查询、告警智能问答、报告自动生成、运维知识问答，数据不出内网。 |
| 模型反馈闭环 | 运维标记告警"准确/误报/漏报"、确认根因、采纳处置建议，反馈数据用于模型在线训练持续优化。 |

## E. 技术架构

### E.1 总体架构（四大平台 + AIOps）

参考建行"龙舟运维平台"的OASIS生态化运维模型，采用"搭平台、做场景"思路，自下而上构建四层平台，叠加AIOps智能能力，两地三中心多活部署。

```
┌─────────────────────────────────────────────────────────────┐
│                    场景应用层 (Eco-Ops 生态)                  │
│  监控告警  自动化运维  容量管理  安全合规  智能助手  定制场景…   │
├─────────────────────────────────────────────────────────────┤
│                    AIOps 智能运维层                           │
│  感知(异常检测/动态基线)→认知(知识图谱/根因)→决策(预测/推荐)   │
│  → 执行(Runbook/自愈)   Spark MLlib + XGBoost + 行内大模型      │
├─────────────────────────────────────────────────────────────┤
│                    业务平台 (Business Platform)                │
│  共性服务组件：监控/告警/自动化/流程/CMDB/通知/报表/权限审计     │
│  服务目录 + API网关 + 微服务自监控   Spring Boot + Nacos       │
├─────────────────────────────────────────────────────────────┤
│                    数据平台 (Data Platform)                    │
│  统一运维数据模型  |  Spark Streaming(实时) + Spark SQL(批)    │
│  MLlib(模型训练推理)  |  Kafka(数据缓冲/订阅)                  │
├─────────────────────────────────────────────────────────────┤
│                      存储层                                  │
│  ES(告警/事件/日志/向量)  +  MySQL(元数据/规则)  +  Redis(热缓存)│
│  +  HDFS(历史指标归档)  +  Neo4j(服务依赖拓扑)                 │
├─────────────────────────────────────────────────────────────┤
│                    采控平台 (Collection & Control)             │
│  分布式采控：Prometheus/Zabbix/SNMP/JMX/Syslog/Filebeat/      │
│  SkyWalking/OpenTelemetry  |  跨数据中心统一纳管  |  插件化扩展 │
└─────────────────────────────────────────────────────────────┘
```

### E.2 关键技术选型说明（四大平台）

| 层次 | 选型 | 理由 |
|------|------|------|
| 微服务框架 | Spring Boot + Spring Cloud Alibaba | 银行主流生态，Nacos注册配置、Sentinel限流熔断，国产化适配好。 |
| 实时计算 | Spark Streaming | 与Spark SQL统一引擎，微批满足毫秒级采集/1秒级运算与≤15s告警时延。 |
| 存储 | Elasticsearch | 告警/事件全文检索、多维聚合、冷热索引，Dense Vector支撑向量检索。 |
| 消息队列 | Kafka | 高吞吐、削峰填谷，支撑日均500亿运维数据。 |
| 缓存 | Redis | 规则热缓存、告警去重窗口、限流计数。 |
| 规则DSL | 自定义DSL + 编译为Spark执行计划 | 可视化、版本化、可灰度、可回滚。 |
| AI/ML框架 | Spark MLlib + XGBoost + Prophet | 与Spark统一引擎，支撑异常检测、根因、时序预测。 |
| 拓扑存储 | Neo4j | 服务依赖知识图谱存储，支撑根因分析图遍历。 |
| 对话大模型 | 行内私有化大模型 | 银行数据安全要求，告警/指标数据禁止出内网。 |
| 采控 | 分布式采控 + 插件化适配器 | 跨数据中心统一纳管，新增监控源只需开发适配器。 |

## F. 非功能需求

### F.1 性能

* 采控吞吐量：≥ 100万条/秒，支撑10万+节点毫秒级采集、1秒级运算。
* 规则匹配时延：P99 ≤ 3s（从指标入Kafka到告警生成）。
* 端到端告警时延：≤ 15s。
* 风暴抑制处理：≥ 10万条/分钟告警输入下，输出收敛比 ≥ 80%。
* 页面响应：常规查询 ≤ 2s，复杂报表 ≤ 8s。
* 场景应用并发：≥ 100个运维场景APP同时运行。

### F.2 可用性与可靠性

* 平台可用性 ≥ 99.95%。
* 两地三中心多活部署，核心服务多实例无单点，支持数据中心级容灾切换。
* 数据零丢失：Kafka多副本(acks=all) + ES副本 ≥ 1 + MySQL主从半同步。
* 故障恢复：RPO = 0，RTO ≤ 5分钟。
* Spark Streaming Checkpoint保证Exactly-Once，死信队列+补偿任务保障最终一致。

### F.3 安全

* 符合等保三级、《商业银行信息科技风险管理指引》要求，全链路HTTPS。
* 对接行内4A统一身份认证，基于RBAC的细粒度权限，支持按系统/团队/数据中心数据隔离与多租户。
* 所有操作留痕，审计日志留存 ≥ 180天，支持追责。
* 敏感指标（如交易类）数据加密存储，数据不出内网。
* 接口限流防刷、防重放，定期漏洞扫描与渗透测试。

### F.4 可扩展性

* 采控插件化：指标源、采控脚本可插件化扩展，新增监控源只需开发适配器。
* 规则DSL可扩展：新增规则类型只需扩展DSL语法与编译逻辑。
* 场景应用生态化：基于服务目录与开发平台，支持内外部团队共创运维场景APP。
* Spark/ES/Kafka/Neo4j 集群水平扩展，支持线性扩容。

### F.5 可维护性

* 规则可视化、版本化，运维自助配置，灰度发布机制。
* 完善的监控自监控（平台自身指标暴露）。
* 运维场景应用全生命周期在线管理，集中代码托管与版本控制。

## G. 验收标准

1. 接入 ≥ 100,000 台监控目标，日均运维数据 ≥ 500 亿条，两地三中心稳定运行 7×24h 连续 30 天无重大故障。
2. 核心指标端到端告警时延 P99 ≤ 15s，采控支持毫秒级采集、1秒级运算。
3. 模拟核心交易系统数据库宕机场景，告警风暴输入 ≥ 100,000 条/分钟，风暴抑制后输出收敛比 ≥ 80%，且根因告警正确输出（Top3准确率≥75%）。
4. 规则从设计到全集群生效 ≤ 30s，撤回 ≤ 10s；投产日版本自动化部署率 ≥ 90%。
5. 通过等保三级测评，审计日志完整可追溯，敏感数据不出内网。
6. 智能异常检测误报率 ≤ 5%，故障自愈覆盖率 ≥ 50%。
7. 沉淀 ≥ 100 个运维场景应用，服务目录标准化接口可用率 ≥ 99.9%。

## J. 关键设计决策记录（ADR）

| 决策 | 选择 | 备选 | 理由 |
|------|------|------|------|
| 整体架构模式 | 四大平台+OASIS生态模型 | 烟囱式工具堆砌 | 参考建行龙舟平台，共性组件下沉平台，上层场景共创，解决烟囱化碎片化。 |
| 实时计算引擎 | Spark Streaming | Flink | 与Spark SQL统一引擎降低运维成本；微批满足毫秒级采集/1秒级运算与≤15s告警时延。 |
| 规则执行方式 | DSL编译为Spark执行计划 | 硬编码规则 | 可视化、版本化、可灰度、可回滚。 |
| 告警存储 | ES | HBase | 需全文检索与多维聚合，ES生态更成熟，Dense Vector支撑向量检索。 |
| 拓扑存储 | Neo4j | ES/关系表 | 服务依赖知识图谱需高效图遍历与中心度计算，Neo4j原生图存储更优。 |
| 服务间通信 | Kafka为主+Feign为辅 | 全同步RPC | 高吞吐解耦，告警链路容忍最终一致。 |
| 风暴抑制 | 拓扑关联+时间窗口+RCA | 仅时间窗口 | 仅去重无法解决根因定位，拓扑关联更贴合银行场景。 |
| AIOps算法框架 | Spark MLlib + XGBoost + Prophet | 独立Python/Flink ML | 与Spark统一引擎，复用集群资源，减少运维组件。 |
| 对话大模型 | 行内私有化大模型 | 公有云LLM | 银行数据安全要求，告警/指标数据禁止出内网，私有化部署满足合规。 |
