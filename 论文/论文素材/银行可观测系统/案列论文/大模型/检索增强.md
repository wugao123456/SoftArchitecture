# 监控告警数据中台 - RAG 智能运维模块扩充说明（PRD 补充）

> 本文档为《全国性股份制商业银行监控告警数据中台 PRD》的智能模块扩充版，重点围绕"检索增强生成（RAG）"对智能知识库（D.11）与智能对话运维助手 AIOps Copilot（D.13）进行细化，并补充相应的背景、技术栈与架构决策，使项目更贴合"大模型应用"主题。

---

## A. 项目背景扩充（大模型与 RAG 引入动因）

在完成统一采集、规则集中化与告警风暴抑制等基础能力后，该行运维体系仍面临三大智能化瓶颈：

1. **知识断层**：告警处置经验散落在资深运维工程师头脑、零散 Wiki 与历史工单中，新人排障高度依赖"传帮带"，平均故障定位时间（MTTA）居高不下。
2. **工具割裂**：运维人员需在告警平台、CMDB、日志系统、变更系统、ITSM 工单之间频繁切换，跨系统关联分析耗时占故障处置总时长的 40% 以上。
3. **大模型落地障碍**：行内已试点私有化部署大模型，但直接用于运维问答时存在三大问题——模型参数知识更新滞后（无法感知最新告警与变更）、缺乏行内专属运维知识（架构拓扑、Runbook、故障案例）、生成结果存在事实偏差与"幻觉"，无法直接用于生产决策。

为此，项目组决定在监控告警数据中台中引入 **检索增强生成（RAG）** 技术，构建"智能知识库 + AIOps Copilot"双轮驱动的智能运维能力：先将行内多源运维知识结构化入库并向量化，再通过向量检索将相关上下文注入大模型提示词，从而提升回答的准确性、时效性与可追溯性，实现从"被动救火"到"智能问答 + 辅助决策"的跨越。

## B. 智能知识库扩充（D.11 RAG 知识库构建）

### B.1 知识来源（多源异构）

| 知识类型 | 来源系统 | 内容示例 | 更新频率 |
|---------|---------|---------|---------|
| 故障案例库 | 告警事件处置记录 | 现象、根因、处置步骤、恢复验证 | 事件关闭后自动提取 |
| Runbook 预案库 | 运维标准化文档 | 重启服务、扩容 Pod、流量切换等标准流程 | 季度审核更新 |
| 架构拓扑文档 | CMDB + 架构 Wiki | 服务依赖、部署架构、网络拓扑 | 变更触发同步 |
| 运维规范手册 | 行内制度文档 | 变更流程、值班规范、应急预案 | 年度修订 |
| 告警规则说明 | 规则引擎 | 规则含义、阈值依据、误报处理 | 规则变更同步 |
| 历史告警与日志 | Elasticsearch | 同类告警历史模式、日志关键字 | 实时增量 |

### B.2 知识库构建流水线（RAG 离线链路）

| 环节 | 技术实现 | 作用 |
|------|---------|------|
| 文档解析 | Apache Tika + 自定义解析器 | 解析 PDF、Word、Markdown、HTML、纯文本，提取正文、表格、标题层级 |
| 文本清洗 | 正则 + 规则引擎 | 去除页眉页脚、目录、水印、重复段落，统一编码与标点 |
| 文档切分（Chunking） | 基于语义标题 + 固定长度滑动窗口（重叠 20%） | 按章节/段落切分为 300~800 字的语义块，保留上下文关联 |
| 元数据标注 | 自动提取 + 人工审核 | 为每个 Chunk 标注来源、系统、文档类型、更新时间、权限标签 |
| 向量化（Embedding） | 私有化部署中文 Embedding 模型（bge-large-zh） | 将文本块转换为 1024 维稠密向量，捕获语义相似度 |
| 向量存储 | Elasticsearch Dense Vector 字段（复用现有 ES 集群） | 支持近似最近邻（ANN）检索，k-NN 检索延迟 < 50ms |
| 索引构建 | ES HNSW 索引（m=16, ef_construction=200） | 保障高维向量检索的召回率与查询性能 |

### B.3 知识更新与版本管理

| 功能 | 描述 |
|------|------|
| 增量入库 | 监听文档源变更事件（Kafka 消息驱动），仅对变更文档重新解析、切分、向量化 |
| 版本管理 | 知识块带版本号与时间戳，支持历史版本回溯与对比 |
| 过期清理 | 按知识类型设置 TTL，过期知识自动下线并归档至冷索引 |
| 质量评分 | 基于被引用次数、用户反馈（有用/无用）、更新时效计算知识质量分，低质量知识触发复审 |
| 权限继承 | 知识块继承源文档的 RBAC 权限标签，检索时按当前用户权限过滤可见知识 |

## C. AIOps Copilot 扩充（D.13 RAG 在线问答链路）

### C.1 RAG 在线检索生成流程

```
用户提问 → Query 改写/扩展 → 混合检索（向量+关键词） → 重排序(Rerank) → 上下文拼接 → Prompt 构造 → 私有化大模型生成 → 引用溯源 → 返回答案
```

| 环节 | 技术实现 | 作用 |
|------|---------|------|
| Query 改写 | 大模型 Few-shot Prompt 将口语化问题改写为标准检索词，并扩展同义词/上位词 | 提升检索召回率，解决用户表达与知识描述不一致问题 |
| 向量检索 | ES Dense Vector k-NN 查询，召回 Top-50 候选块 | 基于语义相似度召回相关知识 |
| 关键词检索 | ES BM25 全文检索，召回 Top-50 候选块 | 补充专有名词、指标名等精确匹配 |
| 混合检索融合 | Reciprocal Rank Fusion（RRF）合并两路结果 | 兼顾语义与关键词，提升整体召回质量 |
| 重排序（Rerank） | 私有化部署 bge-reranker 模型对融合结果重排，取 Top-10 | 对候选块与 Query 做精细语义匹配，提升准确率 |
| 上下文构造 | 按相关性截断拼接，控制总 Token 数 ≤ 4K，保留来源与权限标签 | 为大模型提供精准、可控的参考上下文 |
| 提示词工程 | System Prompt 注入角色设定 + 约束（"仅基于给定上下文回答，不确定时明确说明"） | 约束模型行为，降低幻觉 |
| 模型生成 | 行内私有化大模型（7B~13B 参数，vLLM 推理加速） | 基于检索上下文生成自然语言答案 |
| 引用溯源 | 答案中每个事实性论断标注来源知识块 ID 与文档名 | 可追溯、可核验，增强可信度 |

### C.2 核心问答场景

| 场景 | 示例问题 | RAG 支撑知识 |
|------|---------|------------|
| 告警智能问答 | "这条核心交易系统 P1 告警怎么处理？" | 故障案例库 + Runbook + 同类告警历史 |
| 影响面分析 | "数据库 X 宕机会影响哪些业务？" | CMDB 架构拓扑 + 服务依赖图谱 |
| 变更风险评估 | "今晚发布版本 Y 有哪些风险？" | 历史变更记录 + 故障案例 + 告警规则 |
| 运维规范咨询 | "P0 告警的升级流程是什么？" | 运维规范手册 + 值班制度 |
| 根因辅助排查 | "CPU 突增但内存正常，可能是什么原因？" | 故障案例库 + 指标关联异常知识 |
| 报告生成 | "生成本周核心系统告警周报" | 告警统计 + 故障复盘模板 + SLA 数据 |

### C.3 反馈闭环（人机协同优化）

| 功能 | 描述 |
|------|------|
| 答案反馈 | 用户对答案标记"准确/有误/不完整"，反馈数据写入反馈库 |
| 知识纠错 | 标记有误的答案自动关联到对应知识块，触发知识复审与修正 |
| 检索效果优化 | 基于反馈数据微调 Embedding 与 Rerank 模型，提升检索准确率 |
| 知识沉淀 | 高质量问答对经审核后自动补充入知识库，持续丰富知识覆盖 |

## D. RAG 技术架构补充

### D.1 RAG 专项技术栈

| 层次 | 选型 | 理由 |
|------|------|------|
| 文档解析 | Apache Tika + 自研 Markdown/PDF 解析器 | 兼容行内多格式运维文档，自研解析器保留标题层级用于语义切分 |
| 切分策略 | 语义标题切分 + 固定长度滑动窗口（512 token，重叠 128 token） | 兼顾语义完整性与检索粒度，重叠避免上下文断裂 |
| Embedding 模型 | bge-large-zh（中文，1024 维）私有化部署 | 中文语义理解效果优于通用多语模型，私有化满足数据不出内网 |
| 向量数据库 | Elasticsearch Dense Vector（HNSW 索引） | 复用现有 ES 集群，避免引入 Milvus 等新组件，降低运维成本 |
| 重排序模型 | bge-reranker-large 私有化部署 | 交叉编码器精排，显著提升 Top-K 准确率，推理延迟 < 100ms |
| 检索融合 | Reciprocal Rank Fusion (RRF) | 无参数融合向量与 BM25 结果，效果稳定优于加权线性融合 |
| 大模型推理 | 行内私有化大模型（7B~13B）+ vLLM | 满足银行数据合规要求，vLLM PagedAttention 提升推理吞吐 |
| Prompt 管理 | 模板化 + 版本化管理 | 支持 A/B 测试与灰度切换，便于持续优化提示词 |

│  ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────┐         │

## E. 关键设计决策记录（ADR 补充 - RAG 专项）

| 决策 | 选择 | 备选 | 理由 |
|------|------|------|------|
| 向量数据库 | Elasticsearch Dense Vector | Milvus / Pinecone | 复用现有 ES 集群，减少运维组件；告警数据与知识向量同库便于关联检索；HNSW 索引满足召回与延迟要求 |
| 切分策略 | 语义标题 + 滑动窗口重叠 | 纯固定长度切分 / 纯语义切分 | 纯固定长度易切断语义；纯语义切分块过大影响检索精度；混合策略兼顾语义与粒度 |
| 检索方式 | 向量 + BM25 混合检索 + Rerank | 仅向量检索 | 纯向量检索对专有名词/指标名召回差；混合检索兼顾语义与精确匹配；Rerank 提升最终准确率 |
| Embedding 模型 | bge-large-zh 私有化 | text-embedding-ada-002（公有云） | 银行数据禁止出内网；中文效果更优；私有化部署成本可控 |
| 大模型 | 行内私有化大模型 | 公有云 LLM API | 合规要求，告警/指标/拓扑数据禁止外传；私有化部署满足等保三级 |
| Rerank | bge-reranker 交叉编码器 | 仅向量相似度排序 | 交叉编码器精排效果显著优于双编码器相似度，Top-10 准确率提升约 30% |

## F. 非功能需求补充（RAG 专项）

* 检索延迟：向量检索 P99 ≤ 50ms，端到端问答（含大模型生成）P99 ≤ 8s。
* 检索准确率：Top-10 召回率 ≥ 90%，Rerank 后 Top-3 准确率 ≥ 80%。
* 知识更新时延：文档变更到向量索引更新 ≤ 5 分钟。
* 知识规模：支持 ≥ 100 万知识块的向量检索，索引存储 ≤ 200GB。
* 幻觉率：基于反馈抽样统计，答案事实性错误率 ≤ 5%。
* 高可用：RAG 在线服务多实例部署，大模型推理服务支持多副本负载均衡。

## G. 验收标准补充（RAG 专项）

1. 知识库接入故障案例、Runbook、运维规范等 ≥ 5 类知识源，知识块总量 ≥ 50 万。
2. AIOps Copilot 支持告警问答、影响面分析、规范咨询等 ≥ 6 类场景，端到端响应 P99 ≤ 8s。
3. 答案附带引用溯源，引用准确率 ≥ 95%。
4. 基于 500 条标注问答测试集，答案准确率 ≥ 85%，幻觉率 ≤ 5%。
5. 知识更新链路：文档变更后 5 分钟内可被检索到。
6. 反馈闭环：用户反馈数据可用于模型优化，知识库持续自动丰富。
