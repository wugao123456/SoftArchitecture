一、架构
   场景6要素
     ① 角色(Actor)：与系统交互的用户、外部系统或设备
     ② 环境(Environment)：场景发生的上下文，如正常运行、过载、故障状态
     ③ 刺激/触发(Stimulus)：到达系统的事件或输入，如请求、故障、变更
     ④ 制品(Artifact)：被刺激影响的部分，如模块、进程、数据
     ⑤ 响应(Response)：系统对刺激的反应，如处理请求、恢复服务
     ⑥ 响应度量(Response Measure)：衡量响应质量的可量化指标，如延迟、吞吐量、可用性
     用途：ATAM 架构评估方法的核心，用于评估架构质量属性

   架构风格
     管道-过滤器(Pipe-Filter)
       数据流风格，每个过滤器独立加工数据，通过管道传递
       优点：松耦合、可重用、支持并发
       缺点：不支持交互、性能受最慢过滤器限制
       典型：编译器、ETL、Unix 管道
     客户端-服务器(C/S)
       服务器被动等待请求，客户端主动发起
       典型：Web 应用、数据库
     分层架构(Layered)
       每层只与相邻层通信，自顶向下依赖
       优点：可移植、可复用、关注点分离
       缺点：跨层性能损耗、修改影响层
     事件驱动(Event-Driven)
       组件通过事件总线发布/订阅消息
       优点：松耦合、可扩展
       典型：消息队列、GUI
     微内核(Microkernel)
       核心最小化，扩展以插件方式接入
       典型：操作系统、Eclipse
     解释器(Interpreter)
       解释虚拟指令集，典型：JVM、规则引擎
     黑板(Blackboard)
       共享知识库+多个知识源协同，典型：AI 推理、语音识别
     MVC / MVP / MVVM
       M：模型 V：视图 C：控制器，分离关注点
     微服务架构
       独立部署、服务自治、去中心化治理、按业务能力拆分
     发布-订阅(Pub-Sub)
       解耦生产者消费者，通过主题路由
     代理(Broker)
       中间层协调请求路由，典型：微服务网关

   架构质量属性(质量场景评估)
     性能(Performance)：吞吐量、响应时间、并发数
     可用性(Availability)：MTBF/(MTBF+MTTR)，如 99.99%
     可靠性(Reliability)：无故障运行时间
     可修改性(Modifiability)：变更成本
     可测试性(Testability)：可观测、可隔离
     安全性(Security)：机密性、完整性、可用性
     可伸缩性(Scalability)：垂直伸缩、水平伸缩
     互操作性(Interoperability)：标准接口、协议
     质量属性战术：
       性能：缓存、并发、负载均衡、资源调度
       可用性：心跳、冗余、故障转移、重试
       可修改性：延迟绑定、配置外置、接口抽象
       安全性：认证、授权、加密、审计

   架构评估方法
     ATAM(Architecture Tradeoff Analysis Method)：基于场景，分析敏感点和权衡点，识别风险
     SAAM(Software Architecture Analysis Method)：最早的非功能评估方法
     CBAM(Cost Benefit Analysis Method)：成本-收益分析
     ARID(Active Reviews for Intermediate Designs)

   关键概念
     敏感点(Sensitivity Point)：影响某质量属性的属性(如缓存大小影响性能)
     权衡点(Tradeoff Point)：同时影响多个质量属性(如缓存大提升性能但降低可修改性)
     风险(Risk)：潜在问题，如未验证的假设
     非风险(Non-Risk)：已确认无影响


二、云原生
   可观测性三支柱
     日志(Logs)：离散事件记录，事后分析，ELK/EFK
     指标(Metrics)：聚合数值时序数据，监控告警，Prometheus
     链路追踪(Traces)：请求在分布式系统中的调用路径，Jaeger/Zipkin
     目标：白盒化系统内部状态，支持排障、调优、告警

   Serverless
     FaaS(Function as a Service)：函数即服务，事件驱动、毫秒计费
       典型：AWS Lambda、阿里云 FC
       特点：自动弹性、零运维、按调用计费
       缺点：冷启动延迟、有状态难处理、厂商锁定
     BaaS(Backend as a Service)：后端能力托管，如数据库、存储、认证
     事件驱动架构：由事件触发函数执行

   Service Mesh(服务网格)
     数据平面(Data Plane)：Sidecar 代理接管服务间流量，如 Envoy
     控制平面(Control Plane)：配置下发、策略管理，如 Istio
     核心能力：流量治理、熔断、限流、灰度发布、可观测性、安全(mTLS)
     优点：业务代码与治理逻辑解耦
     与 API 网关区别：网关南北向流量(进出系统)，Mesh 东西向流量(服务间)

   12 因子应用(12-Factor App)
     代码库、依赖、配置、后端服务、构建发布运行、进程、端口绑定、并发、易处理、开发生产等价、日志、管理进程

   云原生四要素
     微服务、容器(Docker)、持续交付(CI/CD)、DevOps

   容器与编排
     Docker：容器化运行时，隔离进程
     Kubernetes：容器编排
       Pod：最小调度单元
       Service：稳定访问入口
       Deployment：声明式副本管理
       Ingress：入口路由
       ConfigMap/Secret：配置与密钥管理


三、面向领域驱动设计(DDD)
   战略设计
     限界上下文(Bounded Context)：一个模型适用的明确边界
       作用：划分领域、防止模型混乱、对齐团队边界
       映射关系：合作、共享内核、客户-供应商、遵奉者、防腐层、开放主机服务、各自独立
     核心领域(Core Domain)：业务价值最高，投入最精资源
     支撑子域(Supporting Subdomain)：辅助核心，可外包但需定制
     通用子域(Generic Subdomain)：通用能力，可直接采购(如认证)
     通用语言(Ubiquitous Language)：团队共享、统一术语，贯穿代码与业务

   战术设计
     实体(Entity)：有唯一标识，状态可变，如订单
     值对象(Value Object)：无标识、不可变，如金额、地址
     聚合(Aggregate)：一组相关对象的一致性边界
     聚合根(Aggregate Root)：聚合对外唯一入口，保证一致性
     领域事件(Domain Event)：领域中发生的业务事实，可异步解耦
     仓储(Repository)：聚合的持久化抽象，像集合一样使用
     工厂(Factory)：复杂对象的创建封装
     领域服务(Domain Service)：无归属但跨实体的业务逻辑
     应用服务(Application Service)：编排领域对象、事务、无业务规则
     防腐层(ACL, Anti-Corruption Layer)：隔离外部系统，翻译模型

   分层架构(DDD 经典四层)
     用户接口层(UI/Interface)：RPC、Controller、DTO
     应用层(Application)：事务、编排、调度
     领域层(Domain)：实体、聚合、领域事件、领域服务
     基础设施层(Infrastructure)：DB、MQ、外部接口


四、分布式
   CAP 定理
     C(Consistency) 一致性：所有节点同一时刻数据一致
     A(Availability) 可用性：每次请求都能得到非错响应(不保证最新)
     P(Partition Tolerance) 分区容错：网络分区时仍能工作
     定理：分布式系统无法同时满足三者，网络分区不可避免，故只能选 CP 或 AP
     CP 典型：ZooKeeper、etcd、HBase、Redis(强一致模式)
     AP 典型：Eureka、Cassandra、Dynamo

   BASE 理论
     Basically Available 基本可用：损失部分可用，如响应变慢
     Soft State 软状态：允许中间状态存在
     Eventually Consistent 最终一致：一段时间后达到一致
     是 AP 的实践补充，互联网大规模系统常用

   一致性模型
     强一致性：写入立即可见，线性一致
     顺序一致性：同一客户端顺序保留
     因果一致性：有因果关系的操作保留顺序
     最终一致性：不立即可见，最终收敛
     读己之所写、单调读、单调写、会话一致性等变体

   分布式事务方案
     2PC(两阶段提交)
       阶段一：协调者发送 prepare，参与者锁定资源
       阶段二：全部 yes 则 commit，否则 rollback
       缺点：同步阻塞、协调者单点、数据不一致、性能差
     3PC(三阶段提交)
       CanCommit → PreCommit → DoCommit
       引入超时，降低阻塞，仍存在数据不一致
     TCC(Try-Confirm-Cancel)
       Try：预留资源；Confirm：确认提交；Cancel：释放资源
       优点：最终一致、可跨服务
       缺点：业务侵入、需保证幂等与空补偿
     Saga
       长事务拆分为多个本地事务，每步有补偿动作
       失败时反向补偿
       编排式(Orchestration)与协同式(Choreography)
       适用：长流程、不强一致场景
     本地消息表
       业务表+消息表同库写入，定时扫描消息表发送
       优点：实现简单、最终一致
       缺点：耦合 DB、延迟较高
     MQ 事务消息(RocketMQ)
       半消息发送 → 本地事务执行 → 提交/回滚消息
       适合异步解耦的最终一致
     最大努力通知
       尽力通知下游，下游主动查询兜底

   分布式 ID
     UUID：无序，索引差
     雪花算法(Snowflake)：时间戳+机器位+序列号
     号段模式：DB 批量取号
     Redis：自增、原子性

   分布式锁
     Redis(setnx+过期)、RedLock 红锁算法
     ZooKeeper(临时顺序节点)、临时节点监听
     对比：Redis 性能高，ZK 强一致可靠

   负载均衡算法
     轮询、加权轮询、随机、最少连接、源地址哈希、一致性哈希
     一致性哈希：解决节点增删导致大量请求迁移，引入虚拟节点


五、ES(Elasticsearch)相关概念
   索引(Index)：文档集合，类似数据库
   文档(Document)：JSON 数据单元，最小可索引单位
   映射(Mapping)：字段类型定义，类似 schema
   分片(Shard)
     主分片(Primary)：水平拆分数据，提升存储与吞吐
     副本分片(Replica)：主分片的拷贝，保证高可用与读吞吐
     主分片数创建后不可改
   倒排索引(Inverted Index)
     词项(Term) → 文档 ID 列表(Posting List)
     核心思想：通过关键词反向定位文档，提升全文检索速度
   分片与副本原理
     写入：先写主分片，再异步/同步复制到副本
     读取：轮询主副本均摊
   集群(Cluster)与节点(Node)
     Master 节点：管理元数据、集群状态
     Data 节点：存储数据
     Coordinating 节点：路由请求、聚合结果
   分词器(Analyzer)
     分三步：字符过滤 → 分词(Tokenizer) → 词项过滤(Token Filter)
     常用：Standard、IK(中文)、Simple、Whitespace
   近实时(Near Real-Time)
     1 秒级延迟，原因：写入先到内存缓冲区，刷新(Refresh)到段才可搜索
   段(Segment)
     倒排索引的物理存储单元，不可变
     合并(Merge)：减少段数量提升性能
   写入流程
     文档 → 内存缓冲 + translog → refresh 生成 segment → flush 落盘
   应用场景
     全文检索、日志分析(ELK)、指标监控、地理位置搜索


六、大模型(LLM)
   核心概念
     Transformer：基于自注意力的神经网络架构，并行能力强
     Self-Attention(自注意力)：序列内每个 token 对其他 token 加权
     Encoder/Decoder：编码器理解、解码器生成
     Token：文本最小单位，模型输入输出粒度
     参数量(Parameter)：模型规模，如 7B、70B

   训练范式
     预训练(Pre-training)：大规模无监督学习，学习语言能力
     SFT(Supervised Fine-Tuning)：指令微调，学会跟随指令
     RLHF(人类反馈强化学习)：偏好对齐
     指令微调 vs 持续预训练 vs 全量微调
     LoRA(Low-Rank Adaptation)：低秩矩阵微调，参数高效
     QLoRA：量化+LoRA，显存友好
     Prompt Engineering：提示工程，Zero-shot / Few-shot / CoT
     Fine-tuning 适用：垂直领域、私有知识

   RAG(检索增强生成)
     流程：用户问题 → 向量检索召回 → 拼接上下文 → LLM 生成答案
     优点：知识可更新、可溯源、幻觉低、无需重训
     组件：Embedding 模型、向量数据库、重排序(Rerank)、LLM
     适用：企业知识库、客服、文档问答

   Agent(智能体)
     感知 → 规划 → 记忆 → 工具调用 → 行动
     ReAct：推理+行动交替
     工具调用(Tool/Function Calling)：LLM 调用外部接口
     记忆：短期(上下文)、长期(向量库)
     多 Agent 协作：CrewAI、AutoGen

   向量化(Embedding)
     将文本映射为高维向量，捕捉语义
     度量：余弦相似度、欧氏距离
     向量数据库：Milvus、Pinecone、FAISS、Chroma、Qdrant
     检索方式：精确检索、近似最近邻(ANN)、HNSW、IVF

   部署与优化
     推理加速：vLLM、TensorRT-LLM、TGI
     量化：INT8、INT4、GPTQ、AWQ
     KV Cache：解码时缓存键值，降低重复计算
     投机解码(Speculative Decoding)：小模型先草拟大模型验证

   应用架构模式
     Copilot：辅助生成(代码、文档)
     对话式 Agent：问答+工具
     工作流(Workflow)：固定步骤编排
     知识库问答：RAG + LLM
     多模态：文本+图像+语音(如 GPT-4V)

   典型风险
     幻觉(Hallucination)：生成看似合理但错误的内容
     安全：提示注入、越狱、数据泄露
     合规：版权、隐私、偏见


七、微服务
   拆分原则
     按业务能力、按 DDD 限界上下文、子域划分
     单一职责、独立部署、数据库独占
   通信方式
     同步：REST、gRPC、Dubbo
     异步：消息队列(Kafka、RabbitMQ、RocketMQ)
   服务注册与发现
     Eureka(AP)、Consul(CP)、Nacos(可切换)、ZooKeeper(CP)
   服务治理
     流量控制、熔断、降级、限流、隔离
     组件：Sentinel、Hystrix、Resilience4j
   网关(API Gateway)
     路由、鉴权、限流、协议转换、聚合
     典型：Spring Cloud Gateway、Kong、APISIX、Zuul
   配置中心
     集中配置、动态刷新，Nacos、Apollo、Config
   链路追踪
     Trace/Span/Sampling，OpenTelemetry、SkyWalking、Zipkin
   数据一致性
     最终一致为主：TCC、Saga、本地消息表、事务消息

   微服务与 SOA 区别
     SOA：企业级、ESB 总线、重量级
     微服务：去中心化、轻量协议、独立部署、数据库隔离


八、消息队列
   作用
     异步解耦、削峰填谷、最终一致、广播
   模式
     点对点(P2P)、发布订阅(Pub-Sub)
   主流产品对比
     Kafka：高吞吐、日志、流处理、分区有序、精确一次
     RabbitMQ：AMQP、灵活路由、低延迟
     RocketMQ：事务消息、顺序、定时、JMS
     Pulsar：存算分离、多租户
   关键概念
     生产者、消费者、Broker、Topic、Partition、Offset
     消费组：组内竞争，组间广播
     分区：提升并行度与扩展性
   可靠性保证
     生产端：ack 确认、重试、幂等
     Broker：副本、刷盘策略
     消费端：手动提交 offset、幂等消费、死信队列
   消息丢失三段防护
     生产：acks=all + 重试
     存储：副本 + 同步刷盘
     消费：手动 ack + 死信
   顺序消息：同分区有序、按 key 路由
   延迟消息：RocketMQ 延迟等级、时间轮


九、缓存
   缓存模式
     Cache-Aside(旁路缓存)：读先查缓存，未命中查 DB 再回填；写先更新 DB 再删缓存
     Read/Write Through：缓存与 DB 同步
     Write Back：只写缓存，异步刷盘
   常见问题
     缓存穿透：查不存在的 key → 布隆过滤器、空对象缓存
     缓存击穿：热 key 失效 → 互斥锁、永不过期
     缓存雪崩：大量 key 同时失效 → 过期时间随机、多级缓存
     缓存一致性：Cache Aside + 延迟双删、消息订阅 binlog(Canal)
   分布式缓存
     Redis：单线程、持久化 RDB/AOF、主从+哨兵、Cluster 分片
     Memcached：纯内存、LRU
   数据结构
     String、List、Hash、Set、ZSet、HyperLogLog、Bitmap、Geo
   淘汰策略
     noeviction、allkeys-lru、allkeys-lfu、volatile-lru、volatile-ttl、random
   高可用
     主从复制、哨兵 Sentinel(故障转移)、Cluster(分片+选举)


十、数据库与存储
   关系型 MySQL
     事务 ACID：原子、一致、隔离、持久
     隔离级别：读未提交、读已提交、可重复读、串行化
     并发问题：脏读、不可重复读、幻读

     锁：行锁、表锁、间隙锁、意向锁、MVCC 多版本并发控制
     日志：Redo(重做)、Undo(回滚)、Binlog(复制)、Relay
     主从：异步复制、半同步、组复制 MGR
     分库分表：水平拆分、垂直拆分、分片键、路由、跨片查询
     中间件：ShardingSphere、MyCat、Vitess

   NoSQL
     KV：Redis、DynamoDB
     文档：MongoDB
     列族：HBase、Cassandra
     图：Neo4j
     时序：InfluxDB、TDengine

   NewSQL
     兼具 ACID 与水平扩展，TiDB、CockroachDB、OceanBase


十一、安全与架构
   安全三要素 CIA
     机密性(Confidentiality)、完整性(Integrity)、可用性(Availability)
   认证与授权
     认证(Authentication)：你是谁，OAuth2、SSO、JWT
     授权(Authorization)：你能做什么，RBAC、ABAC、ACL
   加密
     对称：AES、DES，速度快
     非对称：RSA、ECC，密钥分发
     哈希：MD5、SHA-256
     数字签名：私钥签名、公钥验签
   常见威胁
     SQL 注入、XSS、CSRF、重放攻击、中间人、DDoS
   防护
     WAF、HTTPS/TLS、限流、防火墙、零信任


十二、架构演进与高并发
   单体 → 垂直拆分 → 分布式服务 → SOA → 微服务 → 云原生
   高并发设计三板斧
     缓存：多级缓存、CDN、本地+分布式
