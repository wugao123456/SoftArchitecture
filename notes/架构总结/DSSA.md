### 什么是DSSA？

DSSA（Domain Specific Software Architecture，特定领域软件体系结构）的核心思想是：**与其每个新系统都从零设计，不如在某个特定业务领域中，提炼出一套通用的"架构蓝图"，后续该领域的新项目直接基于这套蓝图快速搭建。**

下面用**电商领域**作为具体例子，完整走一遍DSSA的三个基本活动。

---

### 背景设定

假设某集团公司旗下有多条电商业务线：B2C自营商城、B2B批发平台、跨境电商、社区团购平台。每条业务线都需要独立的电商系统，但核心业务逻辑高度相似。如果用传统方式，每个系统从零开发，大量重复工作。

于是公司决定：**为电商领域构建一套DSSA，让所有电商业务线共享同一套架构蓝图和可复用构件。**

---

### 阶段一：领域分析（获得领域模型）

> 核心目标：**搞清楚电商领域"是什么"** —— 提炼所有电商系统的共性需求和差异点

#### 具体做法

领域分析师 + 领域专家（资深电商产品经理、运营专家、技术专家）一起，调研公司已有的4个电商系统，分析它们的共性：

#### 提炼出的领域模型

**核心业务实体：**

| 实体 | 说明 | 共性/差异 |
|------|------|----------|
| 用户（User） | 买家、卖家、管理员 | 共性：都有注册/登录/权限 |
| 商品（Product） | SKU、分类、属性 | 共性：都有商品信息管理；差异：B2B有批量定价，跨境有多语言 |
| 订单（Order） | 订单头 + 订单行 | 共性：都有下单/支付/发货/售后流程；差异：跨境有清关环节 |
| 库存（Inventory） | 仓库、库存量 | 共性：都有库存扣减；差异：B2C单仓，B2B多仓 |
| 支付（Payment） | 支付单、对账 | 共性：都有支付和退款；差异：跨境有多币种结算 |
| 物流（Logistics） | 运单、轨迹 | 共性：都有物流跟踪；差异：跨境有海关清关 |

**共性业务流程：**

```
浏览商品 → 加入购物车 → 下单 → 支付 → 扣减库存 → 发货 → 物流跟踪 → 确认收货 → 评价
```

**可变点（不同业务线的差异）：**

| 可变点 | B2C自营 | B2B批发 | 跨境电商 | 社区团购 |
|--------|---------|---------|---------|---------|
| 定价策略 | 固定价格 | 阶梯定价/批量折扣 | 多币种+关税 | 团购价/秒杀价 |
| 支付方式 | 支付宝/微信 | 对公转账/信用证 | PayPal/信用卡 | 微信支付 |
| 物流方式 | 快递 | 专线物流 | 国际物流+清关 | 自提/社区配送 |
| 审批流程 | 无 | 采购审批 | 海关申报 | 团长审核 |

**本阶段产出**：电商领域模型（核心实体、共性流程、可变点清单）

### 阶段二：领域设计（获得DSSA）

> 核心目标：**设计出电商领域的通用架构蓝图** —— 一个能适配所有电商业务线的高层架构

#### 参考架构设计

```
┌─────────────────────────────────────────────────┐
│              用户接入层（可变）                      │
│   B2C商城APP  │  B2B采购门户  │  跨境独立站  │ 小程序  │
├─────────────────────────────────────────────────┤
│              API网关（共性）                        │
│   统一鉴权 │ 限流 │ 路由 │ 协议转换                  │
├─────────────────────────────────────────────────┤
│              业务服务层                             │
│  ┌─────────┐ ┌─────────┐ ┌─────────┐            │
│  │用户服务  │ │商品服务  │ │订单服务  │  ← 共性核心  │
│  │(共性)   │ │(共性+   │ │(共性+   │            │
│  │         │ │ 可变点) │ │ 可变点) │            │
│  └─────────┘ └─────────┘ └─────────┘            │
│  ┌─────────┐ ┌─────────┐ ┌─────────┐            │
│  │库存服务  │ │支付服务  │ │物流服务  │            │
│  │(共性+   │ │(共性+   │ │(共性+   │            │
│  │ 可变点) │ │ 可变点) │ │ 可变点) │            │
│  └─────────┘ └─────────┘ └─────────┘            │
├─────────────────────────────────────────────────┤
│              基础设施层（共性）                      │
│   MySQL │ Redis │ Kafka │ ES │ 分布式调度          │
└─────────────────────────────────────────────────┘
```

#### 可变点机制设计

架构中为每个差异点预留了**扩展接口**：

| 可变点 | 扩展机制 | 说明 |
|--------|---------|------|
| 定价策略 | **策略模式** | 定义`PricingStrategy`接口，B2C实现`FixedPriceStrategy`，B2B实现`TieredPriceStrategy`，跨境实现`MultiCurrencyPriceStrategy` |
| 支付方式 | **适配器模式** | 定义`PaymentAdapter`接口，各支付渠道各自实现适配器，新增支付渠道无需改核心代码 |
| 物流方式 | **插件机制** | 定义`LogisticsPlugin`接口，各物流商各自实现插件，通过配置中心动态加载 |
| 审批流程 | **流程引擎** | 使用工作流引擎（如Flowable），不同业务线配置不同的审批流程模板 |

**本阶段产出**：电商领域参考架构 + 可变点扩展机制 + 接口规范

### 阶段三：领域实现（开发和组织可复用构件）

> 核心目标：**把架构蓝图变成实实在在的、可直接复用的代码构件**

#### 构建可复用构件库

| 构件类别 | 具体构件 | 复用方式 |
|---------|---------|---------|
| **基础技术构件** | 统一认证中心（OAuth2.0）、分布式日志组件、统一配置中心、分布式锁工具 | 所有业务线直接引用 |
| **领域共性构件** | 订单状态机引擎、库存扣减引擎（支持乐观锁/悲观锁）、通用商品SPU/SKU模型、统一金额计算工具（防精度丢失） | 封装为独立Jar包/Docker镜像，纳入公司Maven仓库 |
| **可变点构件** | 定价策略包（含B2C/B2B/跨境3种实现）、支付适配器包（含支付宝/微信/PayPal等实现）、物流插件包（含顺丰/中通/DHL等实现） | 各业务线按需选择、组合配置 |
| **脚手架工具** | 基于领域模型自动生成微服务骨架代码、数据库建表脚本、API文档 | 新业务线一键生成项目骨架 |

#### 实际复用效果

当公司要新上线一个**宠物电商**业务线时：

```
传统方式：从零开发，约6个月，20人团队

基于DSSA：
1. 用脚手架工具生成项目骨架 → 1天
2. 引入基础技术构件（认证、日志、配置） → 1天
3. 引入领域共性构件（订单状态机、库存引擎、商品模型） → 2天
4. 选择定价策略：FixedPriceStrategy → 配置即可
5. 选择支付适配器：支付宝+微信 → 配置即可
6. 选择物流插件：顺丰+中通 → 配置即可
7. 仅开发宠物领域特有的功能（如活体运输、宠物健康档案） → 2个月

总周期：约2.5个月，8人团队
```

**复用率约70%，开发周期缩短60%。**

### 三个阶段总结对照

| 阶段 | 核心问题 | 电商领域示例中的关键动作 | 产出物 |
|------|---------|----------------------|--------|
| **领域分析** | 电商领域"是什么" | 调研4个现有电商系统，提炼共性实体、共性流程、可变点 | 领域模型（实体、流程、可变点清单） |
| **领域设计** | 电商系统"怎么建" | 设计分层参考架构，为每个可变点设计扩展机制（策略模式/适配器/插件） | 参考架构 + 接口规范 + 扩展机制 |
| **领域实现** | "用什么来建" | 开发通用构件（订单状态机、库存引擎等），搭建构件库和脚手架工具 | 可复用构件库 + 脚手架工具 |

---

### 一句话总结

> DSSA的本质就是**"一个领域的架构模板 + 一套可复用的构件库"**。领域分析搞清楚这个领域有哪些共性和差异，领域设计画出通用的架构蓝图并预留扩展点，领域实现把蓝图变成可直接复用的代码构件。后续该领域的新项目，只需"选构件 + 填差异"即可快速搭建，真正实现**从"每次造轮子"到"组装轮子"**的跨越。
